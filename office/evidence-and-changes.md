# Доказательства, исходные статусы и изменения

Исходные технические документы и `data/spec-matrix.csv` сохранены как получены. Начальная привязка — `data/office/spec-crosswalk.csv`: 73 устойчивых SPEC-ID, исходная строка, исходные значения/статус и commit. Перенумерация CSV не меняет идентичность требования. При новой ревизии сопоставлять содержание, сохранять прежние ID и явно регистрировать добавления/удаления.

## Исходные статусы

| Статус исходной базы | Что означает для нового офиса |
|---|---|
| CONFIRMED-430 | Заявленное в базе подтверждение по проекту 430; проверить конкретный источник/редакцию перед применением |
| CONFIRMED-HULL listing | Сведение в публикации о корпусе; не отметка фактического обмера или наличия оборудования |
| CONFIRMED-430/HULL | Составная метка; основания по проекту и корпусу должны быть различимы |
| REFERENCE | Другой объект; допустим для сравнения, не для молчаливого переноса в спецификацию |
| PROVISIONAL | Рабочее предположение; не утверждённая конфигурация |
| CONFLICT | Конкурирующие значения сохраняются; усреднять без основания нельзя |
| OPEN, TO-DECIDE | Данных/решения нет |
| TO-MEASURE, TO-DOCUMENT и составные варианты | Требуются измерение, документ и/или решение; сохранить точную исходную метку |
| DESIGN REQUIREMENT | Записанное проектное требование; применимость и источник нормативного статуса ещё подлежат проверке |

В новых реестрах отдельно хранить статус проверки: NOT_CHECKED, DOCUMENT_VERIFIED, MEASURED, CALCULATED, APPROVED_ASSUMPTION, MISSING, CONFLICT, NOT_APPLICABLE с основанием. Отдельно — решение о допустимости применения/выпуска. Маркировка утверждённого допущения не повышает достоверность исходного факта.

## Работа с документами

Приём: файл, источник, дата, ревизия, SHA-256, разрешённая область использования и место хранения. Для чертежа — номер, лист, масштаб и авторство; для КП — поставщик, документ, дата цены, страница/строка. Сначала извлекать явные размеры и денежные значения, затем интерпретировать. Визуальная оценка по фотографии не заменяет размер. Сохранить сырой текст/OCR и координаты при распознавании; сомнительные деньги сверять с изображением и арифметикой.

Ссылку на недоступный документ не считать прочитанным источником. Актуальность нормативов и документов изготовителя проверяется профильным специалистом при отраслевой работе. Исходные интернет-источники репозитория этим офисным переносом повторно не проверены.

## Изменение проекта или бюджета

Сначала CHANGE-ID: инициатор, причина, старая и новая ревизии, затронутые SPEC/WBS/строки сметы, добавления/исключения/замены. Отдельно отразить влияние на объём, цену, состав, срок, уже заказанное и утилизацию/возврат, если применимо.

Проектный руководитель фиксирует затронутые интерфейсы: масса и положение, габариты и доступ, мощность/потребление, крепления, трассы и испытания — по применимости и без самостоятельных морских расчётов. Неизвестное влияние передаётся специалисту. Совпадение общей цены не доказывает техническую эквивалентность.

До решения сохранять базовую версию. После принятия — новая версия, независимая проверка зависимых результатов, обновление прогноза и описи. Сравнение по ID показывает добавленные/удалённые строки и денежный баланс; смена единицы или состава требует содержательной проверки независимо от арифметики.
