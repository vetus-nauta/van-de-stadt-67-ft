# Роли, обязанности и передачи

С 10.09.2026 роли назначены агентам по [действующей организации офиса](agent-office.md); актуальные исполнители и статусы — в реестре назначений. Один исполнитель может совмещать подготовительные роли; автор существенного расчёта не является его независимым проверяющим. Назначения ведутся в `data/office/roles.csv`.

| Роль | Обязанность и результат | Получатель / граница |
|---|---|---|
| HEAD — начальник офиса | Паспорт, состав работ, задания, решения о пробелах, сводный бюджет, внутренний выпуск | Алексей; не выбирает непроверенную техническую конфигурацию ради цены |
| DESIGN — руководитель проектной части | Ведомость требований, ревизии решений, интерфейсы, согласованная спецификация | Сметчик; не выдаёт аналог или объявление за проектное доказательство |
| ESTIMATE — сметчик | Объёмы, единицы, структура затрат, расчёт, баланс версий | Проверяющий; не меняет проектную характеристику молча |
| PROCUREMENT — аналитик предложений | Подлинные КП, комплектность, условия, сопоставимая стоимость, проекты запросов | Сметчик; отправка/заказ по отдельному поручению |
| PLAN — планирование и контроль затрат | Зависимости, сроки, обязательства, факт, остаток и прогноз завершения | Начальник; не смешивает платежи с выполненной стоимостью |
| REVIEW — независимый проверяющий | Протокол по точной версии, пересчёт, классификация замечаний | Начальник; не скрывает правки автора и предел проверки |
| DOCS — выпускающий / документы | Реестры, версии, опись, хеши, комплект передачи | Получатель продукта; не меняет согласованный расчёт |

Передачи:

1. HEAD → DESIGN: цель, границы, исходная спецификация, список неизвестного. Приём: ведомость требований и пробелов с ответственными, без фиктивной технической готовности.
2. DESIGN → ESTIMATE: ревизия решения, позиции, количества/способ получения, единицы, границы комплекта, интерфейсы и ограничения. Приём: каждый объём имеет источник либо согласованное допущение.
3. ESTIMATE → PROCUREMENT: перечень технически определённых позиций, единиц, количества и места/условий поставки. Приём: можно запросить сравнимые предложения; отсутствующее перечислено.
4. PROCUREMENT → ESTIMATE: исходные КП, сроки действия, валюты/налоги, приведение единиц, исключения, сопоставимость. Приём: цена связана с тем же исполнением, а выбор предложения объяснён.
5. ESTIMATE + PLAN → REVIEW: расчёт, исходники, версии, изменения и прогноз. Приём: результат воспроизводится; известны границы всех итогов.
6. REVIEW → HEAD: замечания, влияние, выполненные/невыполненные проверки. HEAD → DOCS: решение по точной версии и состав выдачи.

Каждая передача оформляется [шаблоном](../templates/handoff.md). Получатель ставит ACCEPTED / RETURNED с датой и основанием. Назначение задачи не равно её выполнению. При изменении входа выявляются зависимые задачи и при необходимости вновь открываются проверки.

Узкие специалисты по системам назначаются начальником по [плану специализации](specialization-plan.md), когда определены задачи и критерии допуска. Эта версия не объявляет их обученными.
