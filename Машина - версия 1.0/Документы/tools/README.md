# Локальные инструменты сметного офиса

`office.py` работает на Python 3 без сторонних пакетов. Он выполняет арифметику, сравнивает редакции и составляет контрольные суммы. Утверждение сметы, проверка источников, технической эквивалентности и полномочий согласовавшего остаются задачами отдела.

## Контракт входных данных

CSV: UTF-8, допускается BOM, разделитель `;`, точный порядок заголовков:

```csv
line_id;wbs_id;spec_ids;description;cost_type;quantity;unit;unit_price;currency;price_basis;source_id;status;assumption_id;notes
```

Количество и цена — неотрицательные конечные десятичные числа с точкой, без разделителей тысяч и экспоненты. Пустое значение не означает ноль. `line_id` уникален и сохраняется между редакциями. `spec_ids`, `assumption_id`, `notes` могут быть пустыми; для `APPROVED_ASSUMPTION` ссылка `assumption_id` обязательна. Прочие поля должны быть заполнены. Ссылка на основание цены обязательна, но инструмент не подтверждает существование и достоверность документа.

Допустимы только статусы `CONFIRMED` и `APPROVED_ASSUMPTION`; черновые и неизвестные строки останавливают расчёт. Допущение должно быть заранее согласовано и записано в реестр: один текст статуса этого не доказывает. Каждый входной файл должен содержать хотя бы одну строку.

Все строки одного расчёта должны совпадать с указанными `--currency` и `--price-basis` (`NET` — без налога, `GROSS` — с включённым налогом). Код валюты задаёт оператор; справочник валют не встроен. Налоги, курсы, заготовительно-складские начисления и резервы автоматически не добавляются. Доставка, монтаж и труд при необходимости представлены отдельными согласованными строками. Нельзя одновременно включать их в цену ресурса и отдельный итог.

## Учебный пример

Пример ниже не является проектной сметой; значения и ссылки вымышленные. Сохраните его отдельно от действующих данных, например в `.local/training/estimate-v001.csv`:

```csv
line_id;wbs_id;spec_ids;description;cost_type;quantity;unit;unit_price;currency;price_basis;source_id;status;assumption_id;notes
DEMO-001;DEMO-WBS;DEMO-SPEC;Учебный материал;MATERIAL;2;шт;10.005;EUR;NET;DEMO-SOURCE;CONFIRMED;;Только учебный пример
```

Каталоги создаются оператором заранее. Расчёт создаст новый JSON с итогом `20.01`, основаниями каждой строки, SHA-256 входного CSV и статусом `CALCULATION_ONLY_NOT_APPROVAL`:

```bash
python3 tools/office.py cost .local/training/estimate-v001.csv --currency EUR --price-basis NET --out .local/training/cost-v001.json
```

Сначала округляется произведение количества и цены каждой строки до `0.01` по правилу `ROUND_HALF_UP`, затем складываются округлённые строки. Денежные значения в JSON записаны строками, чтобы не терять десятичную точность.

## Сравнение редакций

```bash
python3 tools/office.py compare .local/training/estimate-v001.csv .local/training/estimate-v002.csv --currency EUR --price-basis NET --out .local/training/comparison-v001-v002.json
```

Оба CSV проходят одинаковый контроль. Сопоставление выполняется по `line_id`; добавления, удаления, изменённые поля и разница итогов выдаются отдельно. Перестановка строк не считается изменением. Изменение наименования, спецификации или источника будет показано даже при неизменной сумме.

При одинаковой единице измерения арифметическое разложение: влияние количества `(q_new − q_old) × p_old`, влияние цены `q_new × (p_new − p_old)`. Поле `rounding_residual` показывает разницу, возникающую при отдельном округлении составляющих и строковых итогов. При смене единицы разложение не выполняется. Любая изменённая строка требует проверки; даже одинаковая единица не подтверждает техническую сопоставимость ресурсов.

## Контрольные суммы комплекта

```bash
python3 tools/office.py manifest --root .local/release-v001 --out .local/release-v001/manifest.json
python3 -m unittest discover -s tests -v
```

Manifest содержит относительный путь, SHA-256 и размер каждого файла. Исключены каталоги `.git`, `.local`, `__pycache__` внутри проверяемого корня и сам выходной manifest. Символьные ссылки и специальные файлы вызывают отказ, чтобы состав комплекта был однозначным. Контрольная сумма фиксирует байты, но не означает проверку содержания или утверждение. На время сборки комплекта файлы должны оставаться неизменными.

Все команды отказываются перезаписывать существующий выходной файл. При невалидном входном CSV результат не создаётся; код завершения `2`, причина — в stderr. Для следующей редакции задавайте новое имя. Программа не обновляет исходные CSV, не конвертирует валюту и не публикует файлы.
