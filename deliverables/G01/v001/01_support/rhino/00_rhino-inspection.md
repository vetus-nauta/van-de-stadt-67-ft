## Размеры и опасность стандартного bbox

`Objects.GetBoundingBox()` всего файла даёт диапазоны X от −24763,117 до +2589,016 мм, Y от −23646,151 до −15117,562 мм, Z от −26113,658 до −20051,183 мм. **Этот охват нельзя выдавать за размеры яхты.** В нём участвуют подписи/вспомогательные кривые, а API для обрезанных поверхностей возвращает существенно расширенные границы.

Контрольный пример #133: обычный bbox по X охватывает **27352,133 мм**, `GetTightBoundingBox` — **32769,049 мм**; выборка реальных кромок — около **20290,821 мм**, сохранённая render mesh — около **20289,877 мм**. Несмотря на название, tight API в данном файле не даёт пригодный габарит обрезанной оболочки. Причина на уровне реализации API отдельно не исследована; сам факт расхождения проверен. В конечные габариты берутся только явно обозначенные методы, API-bbox оставлены для диагностики.

Для **пары #133/#144**, выборка 129 значений параметра каждой кромки даёт охват по X/Y/Z примерно **20,291 × 5,755 × 3,290 м**. Это приближённые размеры охвата двух выбранных наружных поверхностей в координатах файла, **не LOA, не осадка, не высота борта и не размер нынешнего корпуса**. Сохранённая сетка близка, но тоже дискретна; погрешность выборки не оценена и не равна допуску модели. Внутренняя точка поверхности может выходить за охват кромок. Для принятия размеров необходимы сечения/точные экстремумы обрезанных граней и сопоставление с контрольными чертежами и корпусом.

Не вычислялись объёмы, гидростатика, масса, прочность, площадь обшивки или безопасные размеры проёмов. Шесть solid — небольшие локальные детали (#147,156,170,352,423,425), не весь корпус. Открытость наружных граней сама по себе не доказывает производственного дефекта: это формат представления исходной модели.

Отдельные подтверждённые сборки киля, балласта и руля в этом разборе **не установлены**. Их наличие/полнота и соединение с корпусом требуют отдельной сверки исходных листов и CAD; текущая классификация не позволяет считать их смоделированными или отсутствующими на яхте. Охват по Z 3,290 м включает геометрию выбранных поверхностей в мировых координатах и не имеет установленной связи с водной плоскостью или нижней точкой полного судна: напрямую сравнивать его с `Draft` на PDF нельзя.

## Оси и привязки

Проекции сохраняют мировые X/Y/Z без трансформации. По форме корпуса в XY и XZ геометрически распознаются продольное направление X и вертикальное Z; острый нос на стороне больших X. Это визуальное определение ориентации модели, не согласованная судовая система координат. Половины корпуса расположены вокруг Y примерно **−19381,844 мм**. Плоскость подписи и вспомогательной линии #234 имеет Y=−19381,843773828055 мм; это независимая геометрическая согласованность, но не назначенная нами ДП для рабочих чертежей.

В модели имеются подписи **CWL 1250**, **BUILDING FRAMES**, номера −4, −2, 0, 2…48, 49. Геометрия #234 — горизонтальная линия на Z=−24837,674386867988 мм. Подписи CWL расположены рядом, однако базовая плоскость, проектная нагрузка и привязка к нынешней воде не установлены. Нельзя превращать «1250» в текущую осадку. Координаты text origin относятся к размещению надписей, не к шпангоутам: шаг по надписям не является мерой расстояния между конструкциями.

## Пригодность для следующего шага

Можно использовать модель как **историческую геометрическую подоснову наружной формы, палубы, рубки и кокпита**, с ObjectID и зафиксированной ревизией. Для планировки пока не доказаны чистые внутренние высоты, настилы всех помещений, отделочные слои, полный силовой набор, водонепроницаемые переборки, прочностные функции локальных листов и пути извлечения оборудования. Отсутствие названной детали в нашей классификации не означает отсутствия детали на построенном корпусе.

Для будущих намерений FC01–FC04 требуется: установить, что именно удлиняется вперёд; связать подъём крыши с исходными поверхностями и опорами; обмерить кокпит и силовые опоры hardtop; для кормового гаража получить существующий набор, отметки днища/воды, модель тендера, его массу/полный габарит и траекторию боковой загрузки кран-балкой. Нынешняя геометрия кормы не подтверждает возможность такого гаража. Ничего из перечисленного этим разбором не перепроектировано.

## Воспроизведение и источники метода

Из корня репозитория, в изолированном окружении с [requirements-lock.txt](requirements-lock.txt):

```sh
.local/cad-tools/rhino/venv/bin/python deliverables/G01/v001/01_support/rhino/inspect_rhino.py --out-dir .local/G01/rhino/recheck
```

Скрипт только читает 3DM и пишет производные в явно указанную новую или пустую папку `--out-dir`. Если папка уже содержит файлы, запуск прекращается до чтения модели: повторная проверка не переписывает артефакты выпуска. Для следующего повтора задавать новую папку, например `recheck-02`. Установка PyPI сообщает distribution `rhino3dm==8.32.1`, при этом сам модуль сообщает `__version__=8.32.2`; обе строки сохранены в JSON, расхождение не замалчивается. Matplotlib 3.11.1; полный набор зависимостей фиксирован. Численные JSON выводятся с `allow_nan=False`; отсутствующие выборки/сетки обозначаются null (например, Text не имеет sampled edge bounds), не нулевым размером. CSV bbox-поля содержат словарное представление; машинный источник для вложенных данных — JSON.

Официальная документация проверена 10.09.2026: [McNeel File3dm.Read](https://mcneel.github.io/rhino3dm/python/api/File3dm.html), [GeometryBase bbox](https://mcneel.github.io/rhino3dm/python/api/GeometryBase.html), [File3dmObjectTable bbox](https://mcneel.github.io/rhino3dm/python/api/File3dmObjectTable.html), [PyPI rhino3dm](https://pypi.org/project/rhino3dm/). Использованные справки описывают чтение объектов и координатные охваты; не удостоверяют инженерную пригодность модели.
